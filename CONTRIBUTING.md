# Работа с репозиторием

Конвенции для задач, веток, коммитов и PR. Процесс: обсуждение → спека в issue → implementer → CI → приёмка владельцем → squash-мерж

- Язык: заголовок issue, ветки, коммиты - на английском; тело issue - на русском.
- Метки issue `feature`, `bug`, `chore`, `docs`, `refactor`.
- Ветка от свежего `master`: `type/<issue>-short-slug`.
- Коммиты - Conventional Commits: `type(scope): summary` (feat, fix, refactor, test, docs, chore, perf, ci, build), повелительное наклонение, до ~72 символов. Сгенерированное (миграции, lock-файл) и механическое (переименования, форматирование) - отдельными коммитами.
- Один PR - одна фича, без «заодно».
- PR открывается как draft. После зелёного CI основная сессия переводит его в «ready for review» вместе с комментарием `[claude summary]`: решения, чувствительные места и что не проверено. Draft = реализация и проверки ещё не завершены.
- Агент не мержит сам.

## Роли

**Владелец** отвечает за продукт и ключевые технические решения: одобряет спеку, принимает PR на превью, даёт фидбэк в чате и мержит. Работа завершена после мержа.

**Основная сессия (техлид)** готовит спеку, запускает агентов, ждёт CI фоновым скриптом, передаёт задачи между агентами, разбирает спорные вопросы и помогает застрявшим агентам. Код сама не пишет и diff целиком не перечитывает без запроса.

**`implementer` (разработчик, `Agents/implementer.md`)** реализует фичу, проверяет, доставляет через GitHub, чинит правки.
