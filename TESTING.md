# Принципы тестирования

- Один тест проверяет один сценарий с понятным риском - по падению видно, какое поведение нарушено
- Проверять наблюдаемый результат. Точные тексты, состав меню и другие детали интерфейса проверять, только если они входят в требование - иначе смена интерфейса ломает тест при рабочей функции
- Выбирать самый дешёвый уровень, который проверяет нужное поведение. E2E использовать для связок, которые важно проверить в браузере
- Перед добавлением теста назови конкретную поломку и проверь, ловит ли её существующий тест. Для общего механизма достаточно одного показательного сценария
- Соразмерять проверку риску: вероятность и последствия поломки должны оправдывать сопровождение теста. Редкие случаи с небольшими последствиями отдельно не покрывать; редкость не отменяет проверки потери данных и нарушения доступа.
- Полный набор вариантов общего поведения держать у его владельца. Обёртки проверять только на собственные риски подключения.
- В асинхронных тестах оставлять настоящий механизм состояния, управлять ответами внешней границы. Проверять состояние до ответа, после успеха и после значимой ошибки; внутренние вызовы фиксировать только там, где они сами являются контрактом.
- Подготовку E2E делать напрямую через тестовые данные, если создание не является предметом сценария. Проверки создания через UI сохранять отдельно.

## Ответственность уровней

- Unit: доменные правила, существенные границы, поведение форм, очереди и восстановление клиентского состояния. Проверять публичный результат; не повторять алгоритм реализации в ожиданиях.
- Integration с БД: ограничения SQL, доступ к данным, квоты, каскады, мягкое удаление, восстановление и миграции. Подмена авторизации не доказывает реальную защиту данных.
- E2E: связка интерфейса, сервера и сохранения; авторизация и навигация; взаимодействия, требующие настоящего браузера, включая DnD и геометрию. Варианты расчётов и валидации оставлять нижним уровням.

Ожидаемое падение (`it.fails`) обозначает известный неисправленный дефект. Его учитывать отдельно от проходящих проверок и явно указывать в отчёте.
