# Принципы тестирования

- Один тест проверяет один риск. Перед добавлением проверь, ловит ли эту поломку существующий тест. Потерю данных и нарушение доступа покрывай даже в редких случаях.
- Проверяй наблюдаемый результат. Точный текст, структуру DOM и внутренние вызовы проверяй, только если они входят в контракт.
- Выбирай самый дешёвый уровень, который ловит поломку. Варианты общего поведения проверяй там, где оно реализовано. У обёрток проверяй их подключение.
- В асинхронных тестах оставляй реальный механизм состояния и управляй ответом внешней системы. Проверяй значимые переходы состояния.
- Готовь данные для E2E через БД. Создавай их через интерфейс, когда проверяешь само создание.
